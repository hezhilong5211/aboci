## 模型与收费

用户已确认新模型沿用旧模型的豆子收费。生产环境旧默认出图模型与 GPT-5.6 Sol 的价格经只读查询核对，本地新模型已按下表配置。

| 模型 | 本地状态 | 豆子收费 |
| --- | --- | --- |
| `gpt-image-2.5-flare` | 默认出图，启用 | 1K 6 豆、2K 10 豆、4K 20 豆，每张 |
| `gpt-image-2.5-sunburst` | 可选出图，启用 | 同上 |
| `gpt-6.1-sol` | 默认对话，启用，Responses 协议 | 输入 25、缓存输入 12、输出 25 豆，每百万 tokens |
| `gpt-5.6-sol` | 停用，保留回退配置 | 同上 |

Luxai Base URL：`https://api.openlux.ai/v1`。复用原账户已有令牌，图像与对话按其原权限使用不同令牌。后台保存后密钥为 `ENC2:` 加密格式，页面脱敏显示；密钥、账户密码与运行配置不进入 Git。

供应商美元报价依令牌分组、输入长度与图片 tokens 变化，与上述产品豆价分开。后台对每个模型可独立调整豆价，前端从模型目录读取，服务端决定扣费。已提交任务保存原模型和价格快照，调价不改变其结算。

公开协议依据：[文生图](https://doc.openlux.ai/en/reference/v1/images/generations?leaf=c%3A1790765112018)、[图生图](https://doc.openlux.ai/en/reference/v1/images/edits?leaf=c%3A1790765179104)、[6.1 价格](https://www.openlux.ai/pricing/model/_?tab=text&name=gpt-6.1-sol)。

## 已实现行为

| 功能 | 实现结果 |
| --- | --- |
| Luxai 出图 | 文生图 JSON、图生图 multipart，有序参考图、URL/base64 结果、尺寸校验；接入原图片队列、并发闸、失败记录及退豆 |
| 6.1 对话 | 流式正文、公开思考摘要、工具循环、看图、规划出图；设置 6.1 默认时停用 5.6，保留其配置 |
| 对话记忆 | 近期原文、增量早期摘要、有效需求与选项、历史素材稳定索引；按用户及会话授权加载旧图，新需求优先 |
| 多会话 | 每会话独立消息、流、模型、草稿及恢复状态；断流继续执行，持久化运行快照，列表显示状态 |
| 模型选择与计费 | 对话及图片模型分别选择，展示后台费率/预计豆数，请求只传模型与参数；扣费、续作、退款使用服务端记录 |

额外修复了并发文本结算、重复图片提交/消费、充值后续作及服务重启补偿边界。同一请求编号不重复扣费；账户行锁配合流水当前读保证 MySQL `REPEATABLE READ` 下的幂等。文本延续原策略，最多扣到实际可用余额；零扣费也保存结算记录，之后充值重试不会补扣旧请求。

记忆摘要调用的供应商成本由平台承担，不另扣用户豆子。原会话保留规则继续生效，记忆与其引用的生成图在会话存续期间保留；不承诺删除会话后永久存图。思考显示仅使用渠道公开的摘要。

## 本地试用与发布

本地后台：`http://127.0.0.1:3000/system/model`。后端：`http://127.0.0.1:8080`。开发小程序目录：`hagent/unpackage/dist/dev/mp-weixin`；发行目录：`hagent/unpackage/dist/build/mp-weixin`。开发包使用本地接口，发行包使用 `https://wxagentshow.mguit.com`。

数据库迁移为 V50（图片任务模型/计费快照与请求幂等、模型占位）、V51（会话记忆及持久运行）和 V52（图片执行期间保留文本最终状态）。迁移只新增停用且无凭据的 Luxai 模型，并在有旧模型时继承其收费；不会直接启用未验证通道。

正式发布步骤：

1. 备份线上数据库和应用包，核对旧收费；确认当前为单后端部署，恢复调度器按此部署结构设计。
2. 发布后端执行 V50/V51/V52，保留原有加密主密钥、微信凭据、数据库/Redis配置。
3. 在后台填入原账户有效 Luxai 令牌，核对上述豆价、参考图能力、质量及尺寸；设 6.1 和 Flare 为默认，核查 5.6 处于停用且配置可回退。
4. 发布后台静态资源；微信上传发行包前完成真实设备验收，再按原微信发布流程提交。
5. 核验新域名下登录、模型目录、文生图、修图、并行恢复、充值与退豆流水。无需再次修改已经保存的微信消息推送 URL。
